# ENG-006 — Transactional writes and returned ids

- **Priority:** P1
- **Type:** Bug
- **Status:** BACKLOG
- **Dependencies:** ENG-005

## Description

Registration, friend accept, and comment deletion commit on one connection. Post inserts return the id Oracle generated.

## Problem Statement

Separate auto-commits leave partial rows. `SELECT MAX(POST_ID)` can attach a file to the wrong post. One friend-request direction is treated as accepted without `STATUS = 'A'`.

## Implementation Scope

In: `withTransaction` for registration and friend accept, `INSERT ... RETURNING` for post, share, and review inserts, timeline filter on both friend directions, comment counter and delete in one transaction.

Out: a visual redesign and unrelated query rewrites.

## Acceptance Criteria

- Registration writes both rows or neither.
- Post creation does not call `SELECT MAX(POST_ID)`.
- Both timeline friend branches require `STATUS = 'A'`.

## Testing Requirements

Unit or integration coverage for registration atomicity and for the id returned by the insert.

## Definition of Done

Tests pass. `MAX(POST_ID)` is gone. Commit contains only this ticket's files.
