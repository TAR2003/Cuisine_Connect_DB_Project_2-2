# ENG-002 — httpOnly session and same-origin API

- **Priority:** P0
- **Type:** Security
- **Status:** BACKLOG
- **Dependencies:** ENG-001

## Description

Issue an httpOnly session cookie from the API. The browser calls `/api` on the same origin through the Vite proxy.

## Problem Statement

The browser stores `userid` in a script-readable cookie and posts it as proof of identity. The UI calls `http://localhost:3001`, which makes a first-party session cookie impossible.

## Implementation Scope

In: `POST /api/login`, `POST /api/logout`, `GET /api/me`, session cookie flags, Vite proxy, relative API URLs with `credentials: 'include'`. Login stops writing the admin cookie.

Out: full ownership checks (ENG-003) and bcrypt (ENG-004). Login may still verify through the existing password check until ENG-004.

## Acceptance Criteria

- `/api/me` without a session returns 401.
- The session cookie is httpOnly and `SameSite=Lax`, and its value is not the user id.
- Frontend fetches use relative `/api` URLs.

## Testing Requirements

Unit tests for cookie flags and the unauthenticated `/api/me` response.

## Definition of Done

Tests pass. Commit contains only this ticket's files.
