# ENG-003 — Authorization and account disable

- **Priority:** P0
- **Type:** Security
- **Status:** DONE
- **Dependencies:** ENG-002

## Description

Every mutating route checks the session actor. Account deletion becomes a disable. Admin routes require `USER_TYPE = 'A'`.

## Problem Statement

Any caller who posts a user id can change or delete that user's data. Admin access is a string compare in the login page.

## Implementation Scope

In: ownership checks from the architecture proposal section 3.4, disable instead of `DELETE FROM USERS`, removal of the client admin backdoor, omission of `PASSWORD` from queries this ticket touches.

Out: bcrypt replacement (ENG-004) and the full schema rebuild (ENG-005).

## Acceptance Criteria

- One user cannot disable another user (403).
- A non-admin cannot call an admin read (403).
- Public profile, menu, and feed reads stay available to any active signed-in user.
- Disabled users fail login and session load.

## Testing Requirements

Unit tests with a stubbed session for the forbidden cases.

## Definition of Done

Tests pass. The client admin branch is gone. Commit contains only this ticket's files.
