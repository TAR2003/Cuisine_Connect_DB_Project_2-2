# ENG-007 — API shape, uploads, modules, README

- **Priority:** P1
- **Type:** Refactoring
- **Status:** BACKLOG
- **Dependencies:** ENG-006

## Description

Return named JSON for converted routes, store uploads outside the frontend source tree, split the server by domain, and make the README match the program.

## Problem Statement

Callers read positional arrays. Uploads land in `frontend/src/public` with no type or size limit. One 4,000-line file hides the boundaries. The README describes controls the code does not have.

## Implementation Scope

In: `{ ok, data }` responses together with the pages that read them, upload allowlist and 5 MB limit, `backend/src/routes/` split, one frontend API client, `adapter-static` SPA served by Express, README rewrite.

Out: SvelteKit upgrade and layout redesign.

## Acceptance Criteria

- An upload extension outside the allowlist is rejected.
- `npm run check` passes for the changed frontend.
- The README contains no password and does not claim real-time chat or a mobile-first layout.

## Testing Requirements

Upload allowlist unit test. `npm run check` in `frontend/`.

## Definition of Done

Checks pass. Existing `/api` paths still exist. Commit contains only this ticket's files.
